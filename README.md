# Кейсы учебной практики

## 1. Сумма между минимумом и максимумом

В корне проекта запустите `python case01/main.py` (Python 3.9 или новее). Сначала введите размер массива. На следующей строке введите числа через пробел.

```text
Размер массива N: 6
Элементы через пробел: 4 -2 10 -3 -8 6
Сумма отрицательных элементов: -3
```

В примере между 10 и −8 стоит только −3. Функция `negative_sum_between_extremes()` складывает отрицательные числа строго между позициями экстремумов. При повторе минимума или максимума она берёт первое вхождение.

## 2. Обычный тур и тур с гидом

Запустите `python case02/main.py`. Для `Tour` программа выводит «Казань» и 15 000 руб. Класс `GuidedTour` переопределяет `description()` и `total_price()`: добавляет пометку «с гидом» и поднимает итог до 17 500 руб. Метод `guide_cost()` возвращает доплату 2 500 руб.

Тесты обеих программ запускаются командой `python -m unittest -v` из корня проекта.

## 3. База «Туризм»

Подключитесь к MySQL 8.0.16 или новее в MySQL Workbench. В чистой схеме выполните `case03/tourism_mysql.sql`, затем запустите `case03/demo_mysql.sql`. Запрос выводит заказ на двоих по 15 000 руб. за место и экскурсию за 2 500 руб. (итого 32 500 руб.). В конце скрипт выполняет `ROLLBACK`, чтобы тестовые записи не остались в базе.

Один заказ относится к одному туру и может включать одну дополнительную услугу. Схему связей можно открыть в Workbench через **Database → Reverse Engineer**.

## 4. Каталог туров на Delphi 10.2, IIS и SQL Server

1. В SQL Server Management Studio выполните `case04/tourism_mssql.sql` один раз в чистой базе. Скрипт создаёт базу `TourismWeb`, таблицу трёх демонстрационных туров и представление опубликованных туров.
2. В Windows установите компонент IIS **CGI** и клиентский драйвер SQL Server, поддерживаемый FireDAC. В Delphi 10.2 с FireDAC откройте `case04/TourCatalog.dpr` и соберите консольный проект Win32 или Win64 с соответствующей разрядностью клиентского драйвера. Сборка без runtime packages упрощает перенос.
3. Создайте отдельный сайт или приложение IIS и пул `TourCatalogPool` с включённой анонимной аутентификацией для учебного стенда. Скопируйте в каталог сайта только `TourCatalog.exe` и `web.config`. У учётной записи пула должны быть права чтения и выполнения в каталоге. В IIS Manager на уровне сервера откройте **ISAPI and CGI Restrictions** и разрешите точный путь к этому EXE. Если IIS блокирует делегирование секций `handlers` или `cgi`, администратор может перенести настройки этих секций для конкретного сайта в `applicationHost.config`. Параметр `createProcessAsUser=false` запускает CGI от имени пула.
4. Для локального SQL Server под администратором SQL выполните команды ниже. Они дают приложению доступ на чтение представления. По умолчанию каталог подключается к `localhost`; для именованного или удалённого экземпляра укажите `TOURISM_SQL_SERVER` в среде процесса IIS и используйте Windows-идентичность, доступную на экземпляре SQL Server.

   ```sql
   USE master;
   CREATE LOGIN [IIS APPPOOL\TourCatalogPool] FROM WINDOWS;
   GO
   USE TourismWeb;
   CREATE USER [IIS APPPOOL\TourCatalogPool] FOR LOGIN [IIS APPPOOL\TourCatalogPool];
   GRANT SELECT ON dbo.PublishedTours TO [IIS APPPOOL\TourCatalogPool];
   GO
   ```

5. Откройте `http://localhost/TourCatalog.exe` (добавьте порт или виртуальный путь вашего сайта). Появятся два опубликованных тура, а «Карелия <Ладога>» отобразится как обычный текст. Проверьте также три случая. Если снять с публикации все туры, появится сообщение о пустом каталоге. Запрос POST должен вернуть 405 с заголовком Allow. При недоступности SQL Server ожидается 500 без параметров подключения в ответе.

Проверка на стенде Delphi 10.2, IIS и SQL Server пока не выполнена.

Документация: [CGI в IIS](https://learn.microsoft.com/en-us/iis/configuration/system.webServer/cgi), [разрешения CGI в IIS](https://learn.microsoft.com/en-us/iis/configuration/system.webserver/security/isapicgirestriction/), [FireDAC и Microsoft SQL Server](https://docwiki.embarcadero.com/RADStudio/Sydney/en/Connect_to_Microsoft_SQL_Server_%28FireDAC%29).
